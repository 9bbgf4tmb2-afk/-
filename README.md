# سيستم المتجر — نسخة تجريبية 1.0

واجهة عربية RTL تعمل كتطبيق ويب تقدمي (PWA) وتُحفظ بياناتها محليًا في المتصفح أولًا. مصممة للتجربة من الموبايل أو الكمبيوتر.

## الموجود حاليًا
- لوحة رئيسية وتنبيهات نقص المخزون.
- إضافة وتعديل وحذف منطقي للمنتجات، كود/باركود، سعر بيع وتكلفة ومخزون.
- تسجيل فاتورة بأكثر من صنف وخصم المخزون بعد حفظها محليًا.
- طرق دفع: كاش، InstaPay، فيزا، محفظة إلكترونية، مختلط.
- موردون ورصيد افتتاحي وتسجيل الدفعات وحساب المتبقي.
- موظفون ورواتب متفق عليها وتسجيل مدفوعات/سلف وحساب المدفوع والمتبقي للشهر.
- مصروفات وتقارير تشغيلية بسيطة.
- تصدير واستيراد JSON كنسخة احتياطية.
- مزامنة تجريبية اختيارية عبر Supabase لنفس الحساب على عدة أجهزة، مع دمج آخر تعديل لكل سجل.
- قراءة باركود بالكاميرا إذا كان المتصفح يدعم BarcodeDetector؛ وإلا يمكن كتابة الباركود يدويًا.
- ملفات PWA مبدئية للتخزين المؤقت للواجهة.

## ما ليس جاهزًا للإنتاج
- هذه نسخة MVP للاختبار وليست نظام محاسبة معتمدًا. لا تستخدمها كمصدر وحيد للسجلات المالية أو المخزون.
- إيصال الدفع حاليًا يُسجّل اسمه فقط؛ رفع الصور إلى تخزين سحابي آمن غير مفعّل.
- المزامنة تعتمد آخر تعديل لكل سجل، ولا تحل تعارض عمليتين متزامنتين على نفس المنتج. لا تستخدم عدة أجهزة للبيع الفعلي قبل إضافة معاملات خادمية ذرية وحل تعارض المخزون.
- لا توجد صلاحيات مدير/كاشير منفصلة ولا إدارة فروع؛ كل مستخدم يرى سجلات حسابه فقط.
- التقارير ليست صافي ربح محاسبيًا؛ لا تشمل تكلفة البضاعة المباعة والمرتجعات والضرائب والتسويات.
- PWA caching لا يضمن أن أول فتح للتطبيق يتم دون إنترنت. افتح التطبيق مرة مع الإنترنت أولًا.
- التخزين المحلي مرتبط بالمتصفح والجهاز؛ حذف بيانات المتصفح قد يحذف البيانات. صدّر نسخة احتياطية بانتظام.
- لا تخزن أرقام البطاقات أو CVV أو كلمات السر أو مفاتيح سرية داخل الملاحظات.

## تشغيل المشروع
يتطلب بيئة Node.js (StackBlitz يمكن أن يوفّر بيئة متصفح عند توفرها في حسابك):
1. ارفع ملفات المشروع إلى مستودع GitHub.
2. افتح المستودع في بيئة تطوير تدعم Vite/Node، ثم نفّذ `npm install` و `npm run dev`.
3. للبناء: `npm run build`.

## تفعيل Supabase
1. أنشئ مشروعًا جديدًا في Supabase.
2. افتح SQL Editor وشغّل `supabase/schema.sql`.
3. في بيئة البناء أنشئ ملف `.env` بناءً على `.env.example` وأضف Project URL و anon/publishable key فقط.
4. أنشئ المستخدمين من Authentication في لوحة Supabase (عطّل التسجيل العام إذا لا تحتاجه).
5. سجّل الدخول من قسم الإعدادات. استخدم نفس حساب Supabase على الأجهزة التي تريد مزامنتها.
6. اختبر بيانات وهمية، ثم صدّر نسخة احتياطية وتأكد من استيرادها قبل إدخال بيانات حقيقية.

## نشر واجهة ثابتة
يمكن نشر نسخة البناء `dist` على خدمة استضافة ثابتة تدعم HTTPS. الكاميرا تتطلب HTTPS أو localhost. لا يحتوي هذا المشروع على أي مفاتيح سرية.
